# 原生运行时内存与性能优化

本次优化移除了所有宠物逐帧复制动作、表情名称列表的开销，并针对 VRM 动画处理减少计算和内存分配：

- 每个变形目标的最终权重只计算一次，顶点循环只处理有效目标。
- 骨骼蒙皮矩阵和动作过渡姿态复用已有缓冲。
- 表情平滑更新直接修改已有条目，避免在每个物理步复制名称字符串。
- CPU 命中检测网格缓存索引映射，在每个分块内共享重复顶点；保留三角形顺序、原有 60,000 索引分块和材质 UV 变换。
- 纹理加载只解码被引用的图像，并移动最后一个引用，缩短重复 RGBA 缓冲的存活时间。

GPU 使用原始三维顶点、材质和纹理，分辨率、帧率配置和动画物理步长沿用原设置。

## 基准结果

2026-11-17，在 Windows、Intel Core i9-14900HX、MSYS2 Rust 1.98.1、现有 release 配置下，对比基线 `ca3f039` 与修改后的相同基准工具。两版交替执行五轮，每轮预热 120 帧、测量 600 帧；表中取五轮结果的中位数。

负载由仓库内原创 VRM 1 测试模型扩展生成：10,201 个顶点、20,000 个三角形、48 个位置变形目标；默认大部分目标不生效，保留追踪、动作和弹簧骨骼处理。它用于测量大量未激活变形目标和共享顶点场景，实际模型的收益取决于其数据。

| 指标 | 基线 | 优化后 | 变化 |
| --- | ---: | ---: | ---: |
| CPU 更新耗时中位数 | 0.8553 ms | 0.0908 ms | 减少 89.4% |
| CPU 更新耗时 P95 | 0.9929 ms | 0.0937 ms | 减少 90.6% |
| 预热后保留堆内存 | 9,105,304 B | 8,349,708 B | 减少 8.3% |
| 更新期间峰值堆内存 | 10,185,520 B | 8,632,924 B | 减少 15.2% |
| 每帧分配/重分配次数 | 8.23 | 2.23 | 减少 72.9% |
| 命中检测顶点数 | 60,000 | 10,201 | 减少 83.0% |

耗时只包含 CPU 动画更新。堆内存通过 Rust 全局分配器统计请求字节数，包含基准工具少量固定开销；解码后的 RGBA 在预热前释放。GPU 资源、命中 alpha 纹理、系统分配器元数据及整个应用 RSS 不在统计范围内。这些数字不能推算成整个应用的内存或 CPU 降幅。命中网格仍会为新一帧的顶点和索引分配缓冲。

## 复现

从仓库根目录执行：

```sh
python tools/benchmarks/vrm_workload.py .runtime/performance/grid-48-morphs.vrm
cargo run --release --manifest-path native/pet_backend/Cargo.toml -p pet-vrm --example runtime_benchmark --locked -- .runtime/performance/grid-48-morphs.vrm 600
```

基准工具也接受真实 `.vrm` 文件。对比其他版本时，使用相同工具、编译配置和模型，交替运行多轮；记录顶点数和目标数量，区分模型加载峰值与稳定更新开销。本次原始运行结果保存在本地 `.runtime/performance/vrm-results.json`。

## 验证

- `cargo test --manifest-path native/pet_backend/Cargo.toml --workspace --locked` 通过；测试集原有的环境依赖忽略项保持忽略。
- 34 项 Python 原生后端、VRM、宠物服务和音乐弹性集成测试通过。
- 新增稀疏变形蒙皮与原逐顶点算法的数值等价测试，覆盖权重合并、截断和缺失目标数据。
- 新增超过 u16 范围的原始索引、跨 60,000 索引分块、共享顶点及 UV 变换测试。
- 新增共享图像源的纹理顺序、像素/透明度和无效缓冲测试。
- VRM 0、VRM 1 和合成大网格的真实 GPU 预览与基线逐像素一致。
- 原生 Live2D、VRM 与像素宠物的 GPU、窗口、截图、IPC 和退出冒烟测试通过。

原生后端需要重新构建后使用这些修改：

```sh
cargo build --release --manifest-path native/pet_backend/Cargo.toml -p bandori-pet-native --locked
```
